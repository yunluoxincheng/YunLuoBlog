# YunluoBlog 管理后台使用指南

## 1. 文档说明

- 文档目标：帮助管理员与开发者快速了解管理后台的页面结构、通用交互和逐页操作流程。
- 路由范围：所有后台页面位于 `/admin/*`。
- 页面覆盖：共 19 个页面（1 个登录页 + 18 个管理页，其中侧边栏导航展示 16 项）。
- 适用项目：`yunluoblog-web` 前端管理端。

## 2. 管理后台架构概述

### 2.1 布局结构（AdminLayout）

管理页统一使用 `AdminLayout`，结构分为三层：

- 左侧边栏：展示后台品牌信息和导航菜单。
- 顶部栏：展示当前页面标题与退出登录按钮。
- 主内容区：承载各管理页面业务组件。

实现要点：

- 布局由 `AuthGuard` 包裹，默认先做认证检查，再渲染页面内容。
- 路由高亮使用“标准化路径 + 前缀匹配”策略，保证子路由（例如 `/admin/posts/edit`）能高亮对应菜单。

### 2.3 路由组织方式

后台页面遵循以下组织规则：

- 登录页：`/admin/login/`（不走后台布局）。
- 管理首页：`/admin/`。
- 功能页：`/admin/<module>/`。
- 文章编辑子路由：
  - 新建：`/admin/posts/new/`
  - 编辑：`/admin/posts/edit?id=<文章ID>`

### 2.4 AuthGuard 认证守卫行为

`AuthGuard` 的认证流程如下：

1. 读取本地 `accessToken`。
2. 若 Access Token 未过期（含 5 秒提前量），直接放行。
3. 若 Access Token 不可用，尝试使用 `refreshToken` 刷新。
4. 刷新成功则放行；刷新失败则清理令牌并跳转登录页。

未登录跳转规则：

- 自动跳转到 `/admin/login/`。
- 附带 `redirect` 查询参数，登录后可回跳到原访问页面。

## 3. 通用交互说明

### 3.1 Toast 通知机制

后台使用 Toast 展示即时反馈，常见场景：

- 成功提示：创建、保存、删除成功。
- 失败提示：接口报错、网络异常、参数无效。
- 警告提示：如未选择文件即上传、JSON 无法格式化等。

变体类型：`success`、`error`、`warning`、`info`。

### 3.2 ConfirmDialog 确认弹窗

删除等不可逆操作统一使用确认弹窗：

- 支持标题、说明文案、确认/取消按钮文案。
- 删除场景通常启用 `danger` 风格（红色按钮）。
- 加载中会禁用按钮，防止重复提交。

### 3.3 FormBuilder 表单机制

多数管理页的“新建/编辑”使用 `FormBuilder`：

- 字段类型：`text`、`textarea`、`select`、`multiSelect`、`number`、`checkbox`。
- 基础校验：必填、数字范围（`min/max`）、自定义校验器。
- 提交行为：先校验，校验通过后抛出 `submit` 事件，由页面组件调用 API。

### 3.4 DataTable 表格机制

大部分列表页使用 `DataTable`：

- 支持分页、列排序、单元格格式化。
- 支持行级操作（编辑、删除、跳转等）。
- 支持空状态、加载态、统一风格操作列。

## 4. 页面使用指南（19 页）

### 4.1 仪表盘（`/admin/`）

#### 功能概述

展示后台关键统计，包括文章总数、已发布数、置顶数、分类数、标签数。

#### 操作流程

1. 进入页面后自动拉取统计数据。
2. 点击“刷新数据”可手动重新加载。
3. 从左侧菜单进入其他管理模块。

#### 关键字段

| 字段 | 说明 |
| --- | --- |
| 文章总数 | 全部文章数量 |
| 已发布文章 | 状态为 `published` 的文章数 |
| 置顶文章 | `pinned = true` 的文章数 |
| 分类数量 | 分类总数 |
| 标签数量 | 标签总数 |

#### 注意事项

- 统计由多个接口并行获取，任一失败会显示错误提示。
- 仪表盘本身不提供直接 CRUD，仅作数据概览与导航入口。

---

### 4.2 文章管理（`/admin/posts/`）

#### 功能概述

分页展示文章列表，支持按状态/分类筛选、跳转编辑、新建与删除。

#### 操作流程

1. 使用“状态筛选”“分类筛选”定位文章。
2. 点击“新建文章”进入创建页。
3. 对某一行点击“编辑”跳转 `edit?id=<id>`。
4. 点击“删除”后在确认弹窗中执行删除。

#### 关键字段

| 字段 | 说明 |
| --- | --- |
| 标题 | 文章标题 |
| 状态 | 草稿 / 已发布 |
| 分类 | 所属分类名称 |
| 标签 | 标签集合 |
| 置顶 | 是否置顶 |
| 更新时间 | 最近更新时间 |

#### 注意事项

- 分页大小固定为 10。
- 删除成功后会自动刷新当前页；若当前页删空会回退上一页。

---

### 4.3 新建文章（`/admin/posts/new/`）

#### 功能概述

创建新文章，支持 Markdown 编辑与预览、分类/标签、发布元信息填写。

#### 操作流程

1. 填写标题、Slug、正文。
2. 选择分类与标签，补充摘要、封面、优先级、作者、许可证信息。
3. 点击“创建文章”。
4. 成功后自动返回文章列表。

#### 关键字段

| 字段 | 说明 |
| --- | --- |
| 标题 | 必填 |
| Slug | 必填；标题输入时可自动生成 |
| 内容 | 必填，Markdown 文本 |
| 分类 | 可选 |
| 标签 | 多选 |
| 状态 | 草稿 / 已发布 |
| 摘要、封面图、优先级 | 展示与排序相关 |
| 作者、许可证名称、许可证链接 | 版权与署名信息 |

#### 注意事项

- Slug 在“未手动编辑”时会随标题自动更新。
- Markdown 预览支持编辑/预览双标签切换，并进行 HTML 安全清洗。

### 4.4 编辑文章（`/admin/posts/edit?id=<id>`）

#### 功能概述

按文章 ID 加载详情并更新内容，字段与新建页一致。

#### 操作流程

1. 通过列表页“编辑”进入页面。
2. 页面读取查询参数 `id` 并加载文章详情。
3. 修改内容后点击“保存修改”。

#### 关键字段

与“新建文章”一致。

#### 注意事项

- URL 必须包含有效 `id` 参数，否则页面会显示错误并提示返回列表。

### 4.16 站点配置管理（`/admin/config/`）

#### 功能概述

按配置 key 管理站点配置，支持 Schema 驱动的表单编辑与原始 JSON 编辑两种模式，配置版本历史查看与回滚。

#### 编辑模式

每个配置卡片支持两种编辑视图，可随时切换：

- **表单视图**（默认）：根据前端定义的配置 Schema 递归渲染友好控件，适合日常配置调整。
- **JSON 视图**：显示原始 JSON 文本编辑器，适合高级用户或 Schema 未覆盖的字段编辑。

#### 操作流程

1. 页面加载配置 key 列表，每个卡片显示 key 名称、中文描述（后端 `description` 字段）、版本号、更新时间。
2. 对某 key 点击"展开编辑"并加载详情，默认进入表单视图。
3. **表单视图下**：通过 Schema 生成的控件修改配置值（见下方控件类型说明）。
4. **JSON 视图下**：直接编辑 JSON 文本，可点击"格式化 JSON"整理格式。
5. 点击"保存配置"提交，或使用 `Ctrl+S` 快捷键保存。
6. 保存成功后提示"配置已保存，重新构建部署后前端页面生效"。

#### Schema 驱动表单控件

表单视图根据字段类型自动渲染对应控件：

| 字段类型 | 控件 | 说明 |
| --- | --- | --- |
| 布尔值 | Toggle 开关 | 切换后不自动保存，需手动确认 |
| 枚举值 | 下拉选择框 | 列出 Schema 定义的 `enumValues` 可选值 |
| 数字 | 数字输入框 | 支持 min/max/step 约束 |
| 短文本 | 单行文本输入框 | 普通字符串字段 |
| 长文本 | 多行文本框 | 如公告内容、简介等标记为 `multiline` 的字段 |
| 对象 | 可折叠分组 | 递归渲染子字段，支持多级嵌套 |
| 数组 | JSON 文本框 | 列表编辑器或降级为 JSON textarea |
| Schema 未覆盖字段 | JSON textarea | 自动归入"其他设置"区域，不丢失数据 |

初始 Schema 覆盖的高频配置：`site`、`comment`、`music-player`、`announcement`、`profile`。其余配置暂使用 JSON textarea 全量编辑。

#### 版本历史与回滚

1. 点击配置卡片中的"查看历史"按钮，按需加载历史版本列表。
2. 历史列表显示：版本号、变更时间、操作人用户名（`displayName`，未设置时显示 `username`）、值预览。
3. 点击"回滚到此版本"并在确认弹窗中确认，即可将历史版本的值写入当前配置。

#### 快捷键

- `Ctrl+S`：保存当前卡片的配置变更。在表单视图和 JSON 视图均适用，仅当存在未保存变更时触发，并阻止浏览器默认保存行为。

#### 未保存变更提示

- 修改配置值后，卡片标题显示橙色圆点标记，提醒有未保存变更。
- 保存成功后标记自动消失。

#### 关键字段

| 字段 | 说明 |
| --- | --- |
| key | 配置标识 |
| value | JSON 值 |
| version | 版本号，每次保存自增 |
| updatedAt | 最近更新时间 |
| description | 后端返回的中文描述说明 |
| changedByName | 历史记录中的操作人用户名 |

#### 注意事项

- JSON 视图下 JSON 为空或语法错误时不可保存。
- 布尔值 toggle 切换后**不会自动保存**，需手动点击保存或 `Ctrl+S`，防止误触。
- 配置列表按 key 排序展示。
- 配置保存后需**重新构建部署**才能在前端页面生效，建议配合 webhook 触发自动重建。
- Schema 未覆盖的字段以 JSON textarea 形式保留在"其他设置"区域，数据不会丢失。

### 4.19 登录页（`/admin/login/`）

#### 功能概述

后台登录入口，负责用户名密码认证与登录态恢复。

#### 操作流程

1. 打开登录页时先尝试恢复会话：
   - 若已有 access token，直接跳转目标页。
   - 若有 refresh token，尝试刷新后跳转。
2. 若未恢复成功，显示登录表单。
3. 输入用户名和密码提交登录。

#### 关键字段

| 字段 | 说明 |
| --- | --- |
| username | 用户名 |
| password | 密码 |
| redirectTo | 登录后跳转地址，来自 URL 参数 `redirect` |

#### 注意事项

- `redirect` 仅允许 `/admin` 前缀路径，非法值会回退到 `/admin/`。
- 登录成功后会写入 access/refresh token；后续管理页由 AuthGuard 统一校验并在必要时自动刷新令牌。

## 5. 常见问题

### 5.1 为什么进入后台会被重定向到登录页？

常见原因：

- 本地没有可用的 access token。
- access token 过期且 refresh token 刷新失败。
- token 被手动清理或已失效。

### 5.2 为什么某些记录不能编辑/删除？

部分页面（如项目、技能、时间线、设备）的行操作依赖后端返回可解析的数字 ID；若数据缺少该 ID，仅可展示不可操作。

### 5.3 导航链接保存为什么提示并发风险？

导航页使用全量替换保存策略。多管理员同时编辑时，后保存者会覆盖先保存者的结构，建议单人串行操作。
